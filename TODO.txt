  ### Remaining 1 failure:

  **misc/sample.grammar.12/g12.c05** — "aaaaaaaa" (8 a's) with grammar `S: A+. A: (A, A)+; "a"+.`
  - Expected: `<S ixml:state="ambiguous"><A>aaaaaaaa</A></S>` (simple flat text in A)
  - Actual: deeply nested tree with `(A,A)+` recursive structure
  - Root cause (deep): `A: (A,A)+; "a"+.` means A[alt=0]=(A,A)+ and A[alt=1]="a"+.
    A[alt=0]'s first child is synthesized rule `--A.f-plus` (not "A" directly).
    `filter_completed_trace` checks if the first matched child == rule name to detect
    direct self-reference. `--A.f-plus` ≠ "A" → not flagged as self-ref → alt=0 is preferred
    (non-self-ref + lower alt_index wins) → recursive structure selected.
  - Fix approaches:
    (a) Trace through synthesized `--` rules to detect TRANSITIVE self-reference back to parent
    (b) Add special case: when alt=0 uses a synthesized rule that contains the parent's name
        in its name (e.g., `--A.f-plus` contains "A"), treat it as effectively self-referential
    (c) Add a "penalize left-recursion-via-synthesized-rules" heuristic in filter_completed_trace
    (d) Swap alt order in the conformance test grammar (changes the grammar, not preferred)
  - Approach (b) is simplest: check if name starts with `--{rule_name}.` in is_self_ref closure

  ### filter_completed_trace rewrite summary (src/parser.rs:1242)
  The previous first-match strategy returned the highest alt_index for nullable rules because
  `queue_front` (LIFO) means last-queued alt lands at deque front and completes first.
  New strategy for user-defined rules: prefer non-directly-self-referential alts, then lower
  alt_index. For synthesized rules (`--` prefix): still first-match (empty zero-factor alt
  completes at prediction time, always first in trace). See memory/project_filter_completed_trace.md.

  ### Caution: synthesized rule dependency
  If X*/X+/X? equivalence rules are refactored (different alt structure), first-match for
  synthesized rules may break if the empty base case is no longer a zero-factor alt.
  See memory/project_synth_rule_dependency.md for mitigation strategies.
