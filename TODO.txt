### Implemented: root alt_index counting (src/parser.rs)
`Parser::is_ambiguous()` counts completed root-rule tasks at `(origin=0, pos=input_len)`.
If two or more distinct alt_indices complete, the grammar is ambiguous. Fixes 4 tests:
date, Battr, iAmb-1, iAlt-1. Wired into `tree_to_test_format_with_state()` in
cmd_parse.rs and cmd_suite.rs.

### Implemented: saturated derivation-signature counting (src/parser.rs)
Each `Task` stores one derivation signature plus a capped `One`/`Many` count. When a
duplicate Earley item arrives with a different signature, or from an already-`Many`
child derivation, the stored item becomes `Many`. `Parser::is_ambiguous()` then marks
completed root items with `Many` as ambiguous. Fixes 5 more tests: ambig, ambig3,
ambig5, expr0, and lf2.

### Attempted: Earley chart structural deduplication (ABANDONED — too many false positives)
The intuition: when a completed task is blocked by deduplication inside `complete()`,
two derivations reached the same chart state — structural ambiguity. In practice this
fires for any grammar using optional rules (`rule?`) because:
1. The predictor eagerly advances a parent over a nullable child (`f-star`, `f-option`)
2. When `complete()` later processes the same child's actual completion, it finds the
   parent advancement already done and deduplicates — but this is NOT a second derivation.
Filtering by "both child and parent consumed input (origin ≠ pos)" reduces false positives
but doesn't eliminate them: rules like `chars: punct, nonpunct?` still trigger because
the optional `nonpunct?` can complete at many different end positions, each creating the
same parent task hash via a different path. Reverting this approach; root counting is
the only safe ambiguity signal available without deeper Earley chart bookkeeping.

### Attempted: duplicate completed root item (ABANDONED — false positives)
Narrowing the dedup signal to "a duplicate task would complete the root rule over the
full input" improves the ambiguous subset (11/15 passing) but incorrectly marks many
ordinary `correct` fixtures ambiguous. `log/root-dup-correct.txt` showed 16 false
failures including address, expr*, ranges, and whitespace/delimiter cases.

### Implemented: reachable derivation-family detection (src/parser.rs) — fixes the last 4
Replaces the forward-propagated One/Many flag (which set Many too late to reach the root)
with detection decoupled from decision:
- `TraceArena.families: HashMap<(name, origin, pos), HashSet<u64>>`. At every dot-completion
  site — `task_advance_cursor` (recorded BEFORE the dedup short-circuit, so a deduplicated
  second derivation still registers) and the empty-rule branch of `predict` — record
  `family_signature(alt_index, matched_so_far)`. Folding in alt_index makes different
  alternatives over the same span distinct families (Mechanism A: ambig6/css/iSepAlt);
  differing child splits make same-alt derivations distinct (Mechanism B: ambig4).
- `is_ambiguous()` is now a read-only reachability walk (`span_is_ambiguous`) from
  (root, 0, n), mirroring `unpack_parse_tree_internal` but over the internal (un-pruned)
  forest so it descends into muted synthesized repetition rules. A span with >=2 families
  is locally ambiguous; reachability from the accepting root excludes dead-end chart items
  (the false positives that sank earlier attempts).
The older One/Many machinery (DerivationCount, derivation_sig, incoming_many) was removed
in commit 65091b1 once the family detector proved out.
